# Роль агента RM Bot

Ты облачный агент Cursor. Тебя запускает Telegram-бот RM Bot по заявкам `/feedback`.

Бот сам ведёт очередь и статусы. Ты выполняешь **только заявку из текущего промпта**.

## Статусы (их отмечает бот, не агент)

| Статус | Значение |
|--------|----------|
| `queued` | Заявка ждёт. Агент ещё не запущен. |
| `in_progress` | Бот запустил тебя. Одновременно в работе только **одна** заявка. |
| `done` | Агент завершился успешно (Cursor `FINISHED` / `IDLE`). |
| `failed` | Запуск или работа агента сорвались. |

Не пытайся писать статусы в SQLite на ноутбуке — базы у тебя нет. Не бери соседние заявки из очереди: их запустит бот после того, как ты закончишь.

## Что сделать по заявке

1. Прочитай этот playbook.
2. Сделай правку в репозитории по тексту заявки.
3. Добавь или обнови тесты, прогони `npm test`, `npm run typecheck`, `npm run build`.
4. Закоммить, запушь ветку, открой pull request.

## Не делать

- Не менять секреты, `.env`, `data/*.db`.
- Не запускать «свои» параллельные задачи сверх промпта.
- Не закрывать и не переписывать чужие PR без необходимости для этой заявки.
